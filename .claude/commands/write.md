메모: $ARGUMENTS

CLAUDE.md의 절대 규칙과 글쓰기 공식을 따른다. 아래 순서를 건너뛰지 말 것.

## 1. 자료 읽기
- `data/blogger-profile.md`, `data/profile.md`, `data/authority-lines.md`, `data/trends.md`, `data/style-profile.md`, `data/photo-guide.md` 를 읽는다.
- `input/photos/` 의 사진(`_mosaic/` 제외)을 **전부 Read로 직접 열어** 본다. 제품명·패키지 문구·가격표·사용 장면·전후 상태를 읽어낸다.
- `input/videos/` 에 영상이 있는지 확인한다.

## 2. 빠진 사실 묻기 (지어내기 금지)
- **협찬 여부**가 메모에 없으면 반드시 묻는다 (내돈내산 / 제품 제공 / 원고료 / 제품+원고료 / 업체 지정 문구 유무).
- CLAUDE.md "살림템 필수 정보 체크리스트" 중 사진·메모로 확인 안 된 항목(구매처·가격·구매 시기·사용 기간·단점 등)을 한 번에 모아 질문한다.
- 매장 방문 글이면 지도용 장소명을 확인한다.

## 3. 개인정보 점검
- 아이 얼굴, 타인 얼굴, 번호판, 송장, 동호수, 단지 표지 등이 보이면 목록으로 알리고 모자이크 승인을 받는다.
- 승인 시 CLAUDE.md의 모자이크 절차(spec 저장 → mosaic.js → 처리본 Read로 육안 확인 → 필요 시 재실행)를 수행한다.

## 4. 설계 → 초안 작성
- 메인 키워드 1개 + 서브 2~3개, 페르소나 1명, 후킹 패턴(trends.md의 최근 사용 기록과 다르게) 을 정한다.
- 사진을 스토리 순서로 배치하고 초안 JSON을 `drafts/YYYYMMDD-슬러그.json` 로 저장한다 (포맷은 CLAUDE.md).
- 협찬이면 blocks[0] = `data/sponsored-disclosure.md` 문구 (일반 text 블록).

## 5. 자가 검수 후 사용자에게 보고
아래를 채팅으로 보여준다:
- 제목 (글자 수) / 메인·서브 키워드 / 키워드 횟수 / 본문 글자 수 / 사진 수 / 인용구 수
- 페르소나, 후킹 패턴, 권위 문구 유형
- 살림템 필수 정보 체크리스트 항목별 ✔/✘
- 가독성 점검: 500자 이상 텍스트 연속 구간 없음 / 인용구·소제목만 훑어도 핵심 전달
- 모자이크 처리 내역 (몇 장·몇 영역·사유)
- 부족한 촬영 컷 (photo-guide 기준)
- **본문 전문 미리보기** (소제목·인용구·사진 위치 표시)

그리고 반드시 질문한다: **"이대로 네이버에 임시저장할까요? (수정할 부분이 있으면 말씀해 주세요)"**
→ 승인 전에는 절대 스크립트를 실행하지 않는다. 수정 요청이 오면 반영 후 다시 보고. 말투·구성 교정 피드백은 `data/blogger-profile.md` 또는 `data/style-profile.md`에 누적 기록한다.

## 6. 승인 후 임시저장
- `node scripts/naver_draft.js drafts/<파일>.json` 실행.
- 로그의 "자동 처리 결과" 블록과 `텍스트대조` 결과를 확인한다.
  - `❌ 불일치`면 성공 보고 금지 → `drafts/<이름>.dump.txt`와 초안 비교, 원인 수정 (셀렉터 문제면 probe → `--dry-run`으로 재시도).
  - 3회 실패 시 `drafts/<이름>.manual.txt` 를 안내.
- `drafts/<이름>.png` 스크린샷을 Read로 확인.

## 7. 마무리 안내
- ❗수동 필요 항목만 안내 + CLAUDE.md 발행 체크리스트(발행 시간대, 24시간 수정 금지, 주 2~3회, 협찬 표기 확인).
- 이번 글의 후킹 패턴·메인 키워드를 `data/trends.md` "최근 사용 기록"에 추가한다.
- 새로 해결한 버그가 있으면 CLAUDE.md "버그 해결 기록"에 남기고, 스크립트가 안정적으로 성공했다면 `scripts/naver_draft.working.js` 로 백업한다.
